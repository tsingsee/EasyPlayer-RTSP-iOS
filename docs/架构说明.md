# EasyPlayer-RTSP iOS 架构与工作流程

本文档描述整个工程的**分层结构**、**端到端播放流程**，以及 `EasyPlayer/` 下各模块的职责。  
开发细节见 [DEVELOPMENT.md](DEVELOPMENT.md)，最小集成见 [INTEGRATION.md](INTEGRATION.md)。

---

## 1. 工程总览

EasyPlayer-RTSP iOS 是一个 RTSP 直播播放器 Demo，核心能力：

| 能力 | 实现层 |
|------|--------|
| RTSP 拉流、解封装 | `libEasyRTSPClient.a` |
| 视频解码 | VideoToolbox 硬解 / FFmpeg 软解 |
| 音频解码 | `EasyAudioDecoder`（G711、AAC 等） |
| 画面渲染 | `kxmovie`（OpenGL ES） |
| 声音输出 | `AudioManager` |
| 录像封装 | `MuxerToVideo` |
| UI 与多路分屏 | `ViewController` + `View` + `Player` |

```
EasyPlayer-RTSP-iOS/
├── EasyPlayer/                 # 应用与播放核心源码
├── EasyPlayerRTSP.xcworkspace  # 主入口（含 Pods）
├── Podfile                     # UI 等第三方依赖
└── docs/                       # 文档
```

## 2. 端到端工作流程

### 2.1 应用启动

用一句话说：**点开 App 图标后，先做播放前的准备工作，然后进入首页流地址列表。**

#### 你会看到什么

1. 闪屏 / 启动画面
2. 进入 **首页**，看到已保存的 RTSP 地址列表（首次安装可能自带一条示例地址）
3. 导航栏可能显示 RTSP 库授权剩余天数

#### 背后发生了什么（按顺序）

| 步骤 | 在干什么 | 为什么要做 |
|------|----------|------------|
| ① 注册软解 | 初始化 FFmpeg 解码能力 | 设置里开「软解码」时需要 |
| ② 激活 RTSP 库 | 校验播放 SDK 是否可用 | 未激活可能无法正常拉流 |
| ③ 读本地配置 | 加载保存过的地址、用户设置 | 软/硬解、是否自动出声、是否自动录像 |
| ④ 首次安装写默认值 | 没有地址时写入示例 URL；默认软解 + 自动音频 | 方便第一次就能试播 |

#### 简图

```
点击 App 图标
      ▼
AppDelegate 启动
      ├─ 准备好解码环境（FFmpeg 注册）
      ├─ 激活 RTSP SDK
      └─ 读出地址列表和设置
      ▼
首页（流地址列表）
      │
      └─ 用户选一条地址 → 见 2.2 点击播放
```

#### 和代码的对应（需要查代码时再看）

| 你想找… | 看哪个文件 |
|---------|------------|
| 启动入口、RTSP 激活 | `Main/AppDelegate.m` |
| 软解注册 | `PlayerDataReader +startUp` |
| 地址列表持久化 | `Model/URLUnit` |
| 软解/自动音频等开关 | `Model/NSUserDefaultsUnit` |

### 2.2 用户点击播放

用一句话说：**你在列表里点一条 RTSP 地址，App 打开播放页，自动开始连摄像头并准备收画面。**

#### 你会看到什么

1. 进入 **播放页**（单路）或 **分屏页**（多路）
2. 画面格子开始转圈 → 状态日志出现「连接中」
3. 连上后 → 「连接成功」，随后出画面、可能有声音

#### 背后发生了什么（按顺序）

| 步骤 | 页面/组件 | 在干什么 |
|------|-----------|----------|
| ① 打开播放页 | `VideoPlayerController` | 展示地址、状态日志、一块播放区域 |
| ② 布局播放格子 | `VideoPanel` | 1 路 / 4 路 / 9 路，每格是一个 `VideoView` |
| ③ 开始播放 | `VideoView` | 用户可见的播放窗口，点播放或自动开播时调用 `startPlay` |
| ④ 创建拉流器 | `PlayerDataReader` | 拿着 RTSP 地址去连网（`EasyRTSP_OpenStream`） |
| ⑤ 等数据回来 | SDK 回调 | 连上、失败、收到首帧等事件 → 更新状态栏；视频包 → 进入 2.3 的解码流程 |

#### 简图

```
首页点某条 RTSP
      ▼
播放页 (VideoPlayerController)
      │  里面有一块 VideoPanel
      ▼
某一个格子 VideoView.startPlay
      │  创建 PlayerDataReader，传入 URL
      ▼
PlayerDataReader 去连 RTSP
      │
      ├─ 事件（连接中/成功/失败…）→ statusView 日志
      └─ 音视频数据 → 见 2.3 解码显示
```

#### 和代码的对应（需要查代码时再看）

| 你想找… | 看哪个文件 |
|---------|------------|
| 播放页、状态日志 | `VideoPlayerController.m` |
| 多分屏布局 | `VideoPanel.mm` |
| 单格播放、按钮、画面 | `VideoView.m` |
| 连 RTSP、收流 | `PlayerDataReader.mm` |

> 分屏时逻辑一样：只是 `VideoPanel` 里同时有多个 `VideoView`，每个地址对应一格。

### 2.3 收流 → 解码 → 显示

用一句话说：**摄像头那边的压缩画面，先通过网络拉下来，再解开变成能画的像素，最后画到屏幕上。**

#### 分 5 步看（视频）

| 步骤 | 谁在做 | 干什么 | 数据长什么样 |
|------|--------|--------|--------------|
| ① 拉流 | `libEasyRTSPClient` | 连 RTSP 地址，把直播数据收下来 | 压缩包（H264/H265，还不能直接画） |
| ② 入队 | `PlayerDataReader` | SDK 回调里把每一包视频先放进队列 | 还在内存里排队 |
| ③ 解码 | 硬解或软解 | 把压缩包还原成图像 | 硬解：VideoToolbox；软解：FFmpeg → YUV |
| ④ 交给 UI | `VideoView` | 收到解码好的一帧 | `KxMovieFrame` |
| ⑤ 画屏 | `KxMovieGLView`（kxmovie） | OpenGL 画到播放窗口 | 你看到的画面 |

音频类似，只是第 ③ 步走 `EasyAudioDecoder`，第 ⑤ 步走 `AudioManager` 出声，不经过 OpenGL。

#### 简图

```
摄像头/录像机
      │  RTSP 网络流
      ▼
libEasyRTSPClient          ← 只负责「拉」，不负责画
      │  压缩视频帧 / 压缩音频帧
      ▼
PlayerDataReader           ← 排队 + 调度解码
      │
      ├─ 视频 ─→ 硬解(HWVideoDecoder) 或 软解(FFmpeg)
      │              │
      │              ▼
      │         VideoView → KxMovieGLView 画画面
      │
      └─ 音频 ─→ EasyAudioDecoder
                     │
                     ▼
                AudioManager 出声
```

#### 硬解还是软解？

看 **设置页「FFmpeg 软解码」开关**：

- **关** → 优先硬解（VideoToolbox，省 CPU）
- **开** → 软解（FFmpeg）
- H.265 且手机不支持硬解 HEVC → 自动改用软解

#### 和 kxmovie 的关系

kxmovie **不解码**，只做两件事：

1. 定义「一帧画面」的数据结构（`KxVideoFrameYUV` / `KxVideoFrameRGB`）
2. 用 `KxMovieGLView` 把这一帧 **画到屏幕上**

所以：**解码在 PlayerDataReader，显示在 kxmovie。**

### 2.4 状态与事件回调（App 层）

SDK 原始事件与业务状态码分层：

```
libEasyRTSPClient
  EVENT_CODEC_*  (EasyRTSPEventCode.h)
        ↓ rtspEventBlock
VideoView → VideoPanel → VideoPlayerController
        ↓ 映射 / 补充
PlayerResultCode (901/902/903…)
        ↓ addStatusCode:
statusView 日志
```

| 层级 | 头文件 | 示例 |
|------|--------|------|
| SDK 事件 | `libEasyRTSPClient/include/EasyRTSPEventCode.h` | `EVENT_CODEC_CONNECTING` |
| App 业务码 | `Player/PlayerResultCode.h` | `901` 硬解、`902` 首帧耗时、`903` 解码失败 |
| UI 状态枚举 | `Player/IVideoStatus.h` | `Connecting` / `Rendering`（仅 UI，非日志主路径） |

### 2.5 播放器初始化：一步一步怎么建起来

用一句话说：**先在启动时准备全局环境，再在播放页把「地址参数」传给播放格子，最后由拉流器真正创建 RTSP 连接。业务层一般不直接调 `EasyRTSP_Init`。**

#### 总流程图

```
① App 启动（全局只做一次）
      │  FFmpeg 注册 + RTSP 授权 + 读设置/地址列表
      ▼
② 进入播放页
      │  创建 VideoPanel，setLayout → startAll
      ▼
③ VideoPanel 把 URLModel 参数赋给 VideoView
      │  url / transportMode / sendOption
      ▼
④ VideoView.startPlay
      │  创建 PlayerDataReader，设置硬解/回调，调用 start
      ▼
⑤ PlayerDataReader（视频子线程）
      │  EasyRTSP_Init → SetCallback → OpenStream
      ▼
⑥ 回调回来
      ├─ 事件 → statusView
      └─ 音视频帧 → 解码 → 画屏/出声（见 2.3）
```

#### 第 ① 步：App 启动（全局一次）

| 顺序 | 做什么 | 关键参数 / 默认值 |
|------|--------|-------------------|
| 1 | `[PlayerDataReader startUp]` | 无参数；内部 `DecodeRegiestAll()` 注册 FFmpeg |
| 2 | `EasyRTSP_Activate(license)` | 授权字符串，如 `"EasyPlayer key is free!"` |
| 3 | 读 `URLUnit` 地址列表 | 没有则写一条示例 `URLModel` |
| 4 | 读用户设置 | 首次默认：`FFmpeg=YES`（软解）、`自动音频=YES` |

位置：`Main/AppDelegate.m`。

> 二次开发同样要在第一次 `startPlay` 之前完成 1、2。

#### 第 ② 步：进入播放页

| 顺序 | 做什么 | 参数 |
|------|--------|------|
| 1 | 首页点一条流 → push `VideoPlayerController` | `pvc.model = 选中的 URLModel` |
| 2 | `viewDidLoad` 创建 `VideoPanel` | frame，例如正方形播放区 |
| 3 | `[panel setLayout:URLs:]` | 单路：`IVL_One`；分屏：`IVL_Four` / `IVL_Nine` |
| 4 | `setLayout` 末尾自动 `startAll:` | 有 `url` 的格子才会开播 |

#### 第 ③ 步：`URLModel` → `VideoView`（播放参数从哪来）

`URLModel.initDefault` 默认值：

| 属性 | 默认 | 含义 |
|------|------|------|
| `url` | （要自己设） | RTSP 地址 |
| `transportMode` | `EASY_RTP_OVER_TCP` (`0x01`) | `0x01` TCP / `0x02` UDP |
| `sendOption` | `0x01` | `0x00` 无心跳 / `0x01` OPTIONS / `0x02` GET_PARAMETER |

`VideoPanel.startAll:` 会把这些赋到格子上：

```
videoView.url          = model.url
videoView.transportMode = model.transportMode
videoView.sendOption    = model.sendOption
[videoView startPlay]
```

位置：`Model/URLModel.*`、`View/VideoPanel.mm`。

#### 第 ④ 步：`VideoView.startPlay`（创建拉流器）

```
先 stopPlay 清旧连接
→ videoStatus = Connecting，显示转圈
→ reader = [[PlayerDataReader alloc] initWithUrl:self.url]
→ 把参数和回调设给 reader
→ [reader start]
```

传给 `PlayerDataReader` 的参数：

| 参数 | 来源 | 说明 |
|------|------|------|
| `url` | `URLModel.url` | RTSP 地址 |
| `transportMode` | `URLModel.transportMode` | TCP / UDP |
| `sendOption` | `URLModel.sendOption` | 心跳方式 |
| `useHWDecoder` | `![NSUserDefaultsUnit isFFMpeg]` | 设置关 FFmpeg → 硬解；开 → 软解 |
| `recordFilePath` | 自动录像开启时 | `PathUnit recordWithURL:` |

三块回调：

| 回调 | 作用 |
|------|------|
| `fetchMediaInfoSuccessBlock` | 拿到媒体信息 → 状态变 `Rendering`，可自动开音频 |
| `frameOutputBlock` | 解码后的一帧 → 画屏 / 缓冲音频 |
| `rtspEventBlock` | 连接/首帧/错误等 → statusView |

位置：`Player/VideoView.m`。

#### 第 ⑤ 步：`PlayerDataReader.start` → 真正连 RTSP

`start` **只起线程**，不在主线程调 SDK：

1. `_running = YES`
2. 启动 `_videoThread`、`_audioThread`
3. 视频线程里调用 `initRtspHandle`

`initRtspHandle` 三步：

```
EasyRTSP_Init(&rtspHandle)
EasyRTSP_SetCallback(rtspHandle, RTSPDataCallBack)
EasyRTSP_OpenStream(... 见下表 ...)
```

`EasyRTSP_OpenStream` 本工程传入值：

| 参数 | 本工程值 | 含义 |
|------|----------|------|
| `handle` | `rtspHandle` | Init 得到的句柄 |
| `_channelid` | `1` | 通道号（本工程固定） |
| `_url` | `self.url` | RTSP 地址 |
| `_connType` | `self.transportMode` | TCP / UDP |
| `_mediaType` | 视频 \| 音频 Flag | 只要音视频帧 |
| `_username` / `_password` | `0` / `0` | 未单独传，认证通常写在 URL 里 |
| `userPtr` | `(__bridge void *)self` | 回调里还原成 `PlayerDataReader` |
| `_reconn` | `1000` | 长连接，断线自动重连 |
| `outRtpPacket` | `0` | 回调完整帧（不是裸 RTP 包） |
| `heartbeatType` | `self.sendOption` | 心跳类型 |
| `_verbosity` | `3` | SDK 日志等级 |

位置：`EasyPlayerReader/PlayerDataReader.mm` 的 `initRtspHandle`。

#### 第 ⑥ 步：停播时怎么拆

```
页面消失 / 点停止
→ VideoPanel.stopAll / VideoView.stopPlay
→ PlayerDataReader.stop
   → SetCallback(NULL)
   → CloseStream
   → Deinit
   → 结束音视频线程
```

#### 查代码对照

| 步骤 | 文件 |
|------|------|
| ① 全局启动 | `Main/AppDelegate.m` |
| ② 播放页 | `ViewController/Play/VideoPlayerController.m` |
| ③ 参数下发 | `View/VideoPanel.mm`、`Model/URLModel.m` |
| ④ 创建 Reader | `Player/VideoView.m` → `startPlay` |
| ⑤ OpenStream | `EasyPlayerReader/PlayerDataReader.mm` → `initRtspHandle` |

更细的代码摘录见 [DEVELOPMENT.md](DEVELOPMENT.md) 第 6 节。

## 3. 模块说明

### 3.1 `Main/`

| 文件 | 作用 |
|------|------|
| `AppDelegate.m` | 启动、RTSP 激活、根导航、Bugly、键盘管理 |
| `Info.plist` | ATS、权限、Bundle 配置 |
| `PrefixHeader.pch` | 全局宏、常用 import |

### 3.2 `libEasyRTSPClient/`

**闭源 RTSP 静态库**，负责网络与解封装，**不负责解码和渲染**。

```
libEasyRTSPClient/
├── libEasyRTSPClient.a
└── include/
    ├── EasyTypes.h           # 帧类型、媒体信息、传输协议常量
    ├── EasyRTSPClientAPI.h   # Init/OpenStream/SetCallback 等 C API
    └── EasyRTSPEventCode.h   # SDK 事件码 EVENT_CODEC_*
```

- 回调：`RTSPSourceCallBack` → 工程内实现为 `PlayerDataReader.mm` 的 `RTSPDataCallBack`
- 输出：`EASY_SDK_VIDEO_FRAME_FLAG` / `AUDIO` / `MEDIA_INFO` / `EVENT_FRAME_FLAG`

### 3.3 `EasyPlayerReader/`

**播放调度核心**，连接 SDK 与解码/UI。

| 文件 | 作用 |
|------|------|
| `PlayerDataReader.h/mm` | 拉流、帧队列、音视频解码线程、录像缓存、事件/首帧耗时上报 |

主要职责：

- 管理 `EasyRTSP_*` 生命周期（`start` / `stop`）
- `RTSPDataCallBack`：入队、更新 `codecID`、转发 SDK 事件
- `videoThreadFunc` / `audioThreadFunc`：从队列取帧并解码
- `frameOutputBlock`：解码后 `KxMovieFrame` 交给 `VideoView`
- `rtspEventBlock`：SDK 事件 + 本地生成的 `PlayerResultCode` 事件

### 3.4 `EasyVideoDecoder/`

**视频解码**（二选一，由设置与 codec 决定）。

| 文件 | 作用 |
|------|------|
| `HWVideoDecoder.m/h` | VideoToolbox 硬解（当前实现偏 H.264） |
| `VideoDecode.c/h` | FFmpeg `avcodec` 软解，输出 YUV |

硬解 / 软解选择逻辑（`PlayerDataReader`）：

- 设置 **未** 勾选 FFmpeg → `useHWDecoder = YES`
- 设置 **勾选** FFmpeg → 软解
- H.265 且设备不支持 HEVC 硬解 → 自动回退软解

### 3.5 `EasyAudioDecoder/`

**音频解码**，将 AAC、G711 等转为 PCM。

| 文件 | 作用 |
|------|------|
| `EasyAudioDecoder.c/h` | 解码入口封装 |
| `AACDecoder.c/h` | AAC |
| `g711.c/h` | G711A/U |

解码后通过 `KxAudioFrame` → `VideoView` → `AudioManager` 播放。

### 3.6 `kxmovie/`

源自 [kolyvan/kxmovie](https://github.com/kolyvan/kxmovie)（LGPL v3），在本工程中**只负责帧数据结构与 OpenGL 渲染**，不负责拉流和解码。

| 文件 | 作用 |
|------|------|
| `KxMovieDecoder.h/m` | `KxMovieFrame`、`KxVideoFrameYUV`、`KxVideoFrameRGB`、`KxAudioFrame` 等帧模型 |
| `KxMovieGLView.h/m` | OpenGL ES 渲染视图，支持 YUV / RGB 两种着色器路径 |

```
解码输出 → KxMovieFrame → VideoView.addFrame: → [kxGlView render:]
```

### 3.7 `Player/`

**播放控件与音频输出**。

| 文件 | 作用 |
|------|------|
| `VideoView.m/h` | 单路播放 UI：按钮、GL 视图、启停、录像/截图、状态机 |
| `AudioManager.mm/h` | 音频会话、PCM 输出 |
| `IVideoStatus.h` | UI 播放状态枚举 |
| `PlayerResultCode.h` | App 层 ResultReceiver 业务状态码（与 Android 对齐） |
| `UIColor+HexColor` | 颜色工具 |

### 3.8 `View/`

**多路布局容器**。

| 文件 | 作用 |
|------|------|
| `VideoPanel.mm/h` | 1/4/9 分屏布局，管理多个 `VideoView`，转发 delegate 事件 |
| `VideoCell` | 首页流列表 Cell |
| `RecordListCell` 等 | 录像/截图列表 UI |

### 3.9 `ViewController/`

**业务页面**。

| 目录/类 | 作用 |
|---------|------|
| `RootViewController` | 首页 RTSP 地址列表 |
| `Play/VideoPlayerController` | 单路播放页，含 `statusView` 状态日志 |
| `Play/SplitScreenViewController` | 4/9 分屏 |
| `EditURLViewController` | 编辑 URL、TCP/UDP、心跳 |
| `ScanViewController` | 扫码添加地址 |
| `Setting/SettingViewController` | 软/硬解、自动音频、自动录像 |
| `Record/*` | 录像列表、截图、回放 |

### 3.10 `Model/`

| 文件 | 作用 |
|------|------|
| `URLModel` | 单路流配置（URL、TCP/UDP、心跳） |
| `URLUnit` | 地址列表持久化（YYKit） |
| `NSUserDefaultsUnit` | 用户设置（FFmpeg 开关等） |
| `PathUnit` | 录像/截图文件路径 |

### 3.11 `MuxerToVideo/`

**录像封装**，播放时若开启录像，`PlayerDataReader` 将编码帧写入 MP4。

| 文件 | 作用 |
|------|------|
| `Muxer.c/h` | 封装逻辑 |
| `MuxerToMP4.c/h` | MP4 输出 |

### 3.12 `ffmpeg/`

预编译 **FFmpeg 静态库**与头文件，供软解、音频解码、录像使用。

```
ffmpeg/
├── lib/    # libavcodec、libavformat、libavutil…
└── include/
```

本工程不直接改 FFmpeg 源码，仅链接 `.a`。

## 4. 关键类怎么配合

用一句话说：**页面管布局，播放窗口管画面，拉流器管连网和解码，GL 视图负责画出来。**

### 4.1 谁管谁（从外到内）

```
VideoPlayerController     播放页：状态日志、导航
        │
        ▼
VideoPanel                分屏容器：1/4/9 格
        │
        ▼
VideoView                 单格播放：按钮、转圈、一块画面
        │
        ├─ PlayerDataReader    连 RTSP、解码、把帧送回来
        │       ├─ HWVideoDecoder / FFmpeg（视频）
        │       └─ EasyAudioDecoder（音频）
        │
        └─ KxMovieGLView         把解码后的帧画到屏幕上
```

### 4.2 两类回调（别混）

| 回调 | 方向 | 传什么 | 用来干什么 |
|------|------|--------|------------|
| **事件** | Reader → View → Panel → 播放页 | 连接中、成功、首帧耗时、解码失败… | 更新 `statusView` 日志 |
| **画面/声音** | Reader → View | 解码好的一帧视频或音频 | 画屏、出声 |

可以记成：

- **事件回调** → 告诉你「进行到哪一步了」
- **帧回调** → 给你「能播的那一帧」

### 4.3 各角色一句话

| 类 | 角色 |
|----|------|
| `VideoPlayerController` | 播放页老板，收事件、显示状态 |
| `VideoPanel` | 多路时管好几个格子，转发事件 |
| `VideoView` | 用户看到的那一格，启停播放 |
| `PlayerDataReader` | 干活的：拉流 + 解码 + 上报事件 |
| `KxMovieGLView` | 只负责画，不解码 |
| `AudioManager` | 只负责出声 |

### 4.4 查代码时打开这些文件

| 关系 | 文件 |
|------|------|
| 播放页 ← Panel | `VideoPlayerController.m` + `VideoPanel.mm` |
| View ← Reader | `VideoView.m` + `PlayerDataReader.mm` |
| View → 画屏 | `VideoView.m` 里 `kxGlView render:` |
| Reader → 解码 | `PlayerDataReader.mm` 里 `videoThreadFunc` |

## 5. 线程模型

| 线程 | 所在模块 | 工作 |
|------|----------|------|
| 主线程 | UI | `VideoView` 布局、`KxMovieGLView` 渲染、事件回调 UI |
| SDK 回调线程 | libEasyRTSPClient | `RTSPDataCallBack` 入队 |
| `_videoThread` | PlayerDataReader | 取视频帧、硬/软解 |
| `_audioThread` | PlayerDataReader | 取音频帧、解码 |
